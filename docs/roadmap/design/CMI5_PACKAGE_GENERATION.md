# cmi5 Package Generation (Next-Gen Learning Interoperability)

## 📋 Overview
The **cmi5 Package Generation** module replaces traditional SCORM with a modern, xAPI-based standard for curriculum delivery. It allows AI agents to "package" curriculum units and teacher extensions into interoperable files that can be launched from any compliant Learning Management System (LMS) while providing deep tracking and offline capabilities.

## 🎯 Key Objectives
1. **Per-Lesson Generation**: Every single lesson plan generated by the system must have its own corresponding `cmi5` package.
2. **Modern Standard**: Adopt `cmi5` (the "xAPI Profile for LMS") to overcome SCORM's limitations in mobile and offline environments.
3. **ODPAR Alignment**: The package content must be strictly aligned with the lesson's Objectives and Assessment criteria, serving as a digital manifestation of the ODPAR system.
4. **Accessible "Reading Module"**: Implement synchronized audio-text highlighting (syllable/word level) for reading passages and instructions.
5. **Interactive Vocabulary Pop-overs**: Allow students to hover/tap on key terms to see definitions, images, and translations directly within the package.
6. **Adaptive Level-Based Delivery (Mastery Sync)**: The package dynamically adjusts content based on the student's **Mastery State** in the database (Levels 1-6).
7. **Offline-Sync Resilience**: Built-in "Pending Sync Queue" for tablet use; xAPI statements are cached locally and synchronized once a school Wi-Fi handshake is detected.
8. **Teacher-in-the-Loop (Draft Mode)**: Teachers can review and "tweak" the Agent's proposed package plan (activities, media, definitions) before its final generation.
9. **Agent-Managed Assembly**: AI agents to automatically assemble Assignable Units (AUs) from the JSON and Vector databases.

## 🛠️ The Connection Architecture

### A. The Data Sources
- **JSON Database**: Provides the "Skeleton" of the lesson (Steps, Objectives, Official Materials).
- **Vector Database**: Provides the "Enrichment" (Vocabulary images, YouTube links, Teacher-added PDFs).
- **Standards Registry**: Links the package to Common Core/NJ Standards via metadata.

### B. The Agent as "Package Architect"
An "Interoperability Agent" performs the following workflow:
1. **Context Retrieval**: Queries the JSON DB for the core lesson structure.
2. **Enrichment Search**: Queries the Vector DB for teacher extensions and related vocabulary.
3. **Instruction TTS Generation**: Automatically triggers Google Cloud TTS to generate audio files for all exercise instructions, ensuring accessibility for struggling readers.
4. **Temporal Syncing**: For reading passages, the agent generates "Sync Maps" (JSON timestamps) that map audio segments to specific syllables/words for real-time highlighting in the UI.
5. **Pop-over Pre-fetch**: Leverages the **Merriam-Webster** or **internal database** to embed definition overlays for tier-2 and tier-3 vocabulary.
6. **Manifest Generation**: Creates the `cmi5.xml` course structure file.
7. **AICC/HACP Wrapper**: Configures the communication launch mechanism.
8. **Quality Check**: Validates that the package contains all media assets and conforms to the `cmi5` specification.

## 📅 Phases

### Phase 1: cmi5 Baseline
- Replace the planned SCORM 2004 module with a basic `cmi5` export utility.
- Generate a simple "Course Structure" XML matched to a curriculum unit.
- Implement basic "Launched" and "Completed" xAPI statements.

### Phase 2: Agent-Enriched Content
- Enable the agent to dynamically embed YouTube videos and PDF expansions from the Vector DB into the package.
- Generate **Leveled Content Sets**: The agent produces 6 different versions of vocabulary definitions and exercises for each lesson.

### Phase 3: Adaptive Learner Profiles
- Implement "Adaptive Launch": The cmi5 package reads the student's proficiency level from the LMS/LRS (or a launch parameter) and automatically activates the corresponding **Level 1-6 UI**.
- Implement "Deep Tracking" (e.g., tracking which specific expansion material a student spent time on).
- Create a dashboard to pull xAPI data back into the application's local analytics.
